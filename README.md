# Cloudflare Family Page Template

家族で資料を非公開で共有するための Web サイトテンプレート。
HTML や画像を Cloudflare Workers Static Assets で配信し、Cloudflare Access で閲覧者を制限。

## Coding Agentを使ってセットアップ

このテンプレートを非公開（Private）のリポジトリにコピーし、クローンしたフォルダを Codex や Claude Code で開く。
次のように依頼する。

> setup-family-page スキルを使って、家族用ページをセットアップしてください。必要なことを順番に聞いて、設定と確認まで進めてください。

スキルが見つからない場合は、`.agents/skills/setup-family-page/SKILL.md` を読んで進めるよう依頼する。

最初に決めるのは、ページの用途、閲覧を許可するメールアドレス、家族のログイン方法。
Cloudflare 上でサイトを管理するための名前（Worker 名）は、用途に合わせて Agent が提案。
たとえば `family-docs` は URL の一部にも使われる名前で、ページに表示するタイトルとは別のもの。

必要なパッケージの確認から、サンプルの公開、閲覧制限の設定、動作確認まで Agent が実行。
利用者が行うのは、アカウントの作成・ログイン、設定内容の確認、秘密情報の入力、最後のブラウザ確認。
操作が必要な場面では、Agent がその場で案内。

## 家族のログイン方法

- **メールで届くコード（One-time PIN / OTP）**：許可したメールアドレスに届く使い捨てコードでログイン。Google 側の準備が不要で、最初に選びやすい方式。
- **Google アカウント**：Google でログイン。Google Cloud Console での事前設定が必要。

どちらも、閲覧を許可する家族のメールアドレスを個別に登録。

## 管理のための認証

家族のログインとは別に、Cloudflare の設定を行うための認証が必要。

- **サイトの公開**：Agent が開始するブラウザ認証で Cloudflare にログイン。
- **閲覧制限の自動設定**：対象アカウントの設定を変更するための API トークンを作成。必要な権限と入力場所は Agent が案内。

API トークンや Google のクライアント シークレットは、チャットに貼り付けない。
専用の入力欄で、値を画面に表示せず入力。
入力した値は設定コマンドの実行中だけ使用し、ファイルには保存しない。
Agent の画面から直接入力できない環境では、案内されたコマンドをローカルのターミナルで一度実行し、結果を伝える。
入力方法はトークンを作成する前に確認。
別ターミナルの操作が難しい場合は、開き方の案内や、利用者が直接入力できる端末の準備を Agent に依頼。

トークンを使いたくない場合は「管理画面で設定したい」と依頼。
Agent が現在の公式手順を確認し、画面ごとに案内。
Agent に管理画面の操作も任せたい場合は、その旨を明示。

自動設定は、同名の Access application が別 Worker を保護している場合や、複数の保護対象を持つ場合には停止する。
また、アカウント内にホスト名・パス単位の Access 設定がある場合も停止する。無関係なサイトの設定も対象となる。
既存設定を削除して回避せず、管理画面で対象サイトの全公開 URL に適用される設定を確認する。詳細は [保守上の判断と制約](docs/design.md#既存リソースの更新)を参照。

## セットアップ完了の確認

最初に公開するのは、テンプレートに含まれるサンプルだけ。
家族の資料を追加するのは、次の確認を終えてから。

- Agent による、未ログインのアクセスがログイン画面へ転送されることの確認
- 利用者による、許可したメールアドレスでページを開けることの確認
- 許可対象外のアドレスには閲覧を許可していないことの確認

OTP は、許可されていないアドレスにはコードが届かない仕様。
画面に「送信した」と表示されても、コードが送られたとは限らない。
コードが届かないことだけで判断せず、Agent と許可者の設定も確認する。
詳しくは [Cloudflare の OTP の説明](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/)を参照。

## セットアップ後の変更

同じ Coding Agent に、変更したい内容を依頼。

> この資料を追加して、サイトに反映してください。

> 閲覧を許可する家族を変更してください。

Agent が対象サイトと変更内容を確認し、必要な設定・公開・再検証を実行。
閲覧者だけを変更する場合は、資料の再公開は不要。
途中から再開するときは、既存サイトの URL を伝える。

## 動作環境と取り扱い

- Node.js 22 以降と npm（macOS、Linux、WSL）
- Cloudflare アカウントと Cloudflare Zero Trust（未設定なら Agent が案内）
- 家族の資料や秘密情報を Git に含めない運用

公開先の閲覧制限と、GitHub リポジトリの公開範囲は別の設定。
コピーしたリポジトリは Private のまま利用。
公開する場合は、現在のファイルと Git 履歴に個人情報や秘密情報が含まれていないことを確認し、所有者が判断。
